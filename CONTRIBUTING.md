# Contributing to SKYNET

Thanks for helping with the Miatoll `17` line. This repository holds documentation and build
tooling only — it is intentionally small and easy to review.

## Ground rules

1. **Never commit the kernel source or build output.** `kernel/` and `out/` are generated by
   [`scripts/sync-source.sh`](scripts/sync-source.sh) and are gitignored. Do not commit
   `Image.gz`, `.img`, `.ko`, `.zip`, `.log` or `.config` artefacts either.
2. **Every commit must be signed off** (`git commit -s`). This matches the upstream kernel's
   Developer Certificate of Origin:
   ```
   Signed-off-by: Your Name <you@example.com>
   ```
3. **One logical change per commit.** Separate docs, scripts and pin bumps.
4. **Update the pin in one dedicated commit.** Change `PINNED_COMMIT` in
   `scripts/sync-source.sh` and the pin listed in `README.md` and
   [`docs/UPSTREAM.md`](docs/UPSTREAM.md) together, then run
   `./scripts/sync-source.sh --check`.
5. **No root/hiding patches in the `17` line by default.** KernelSU, SUSFS and similar
   integrations belong on a separate, clearly named experimental branch.

## Commit message style

Use a short lowercase prefix and an imperative summary:

```
docs: explain Clang LTO requirements
scripts: allow overriding CROSS_COMPILE_COMPAT
defconfig: enable CONFIG_FAKE_UNAME_5_10
upstream: bump pin to <sha>
ci: check Markdown links
```

Explain *why* in the body, and list the device/codename and ROM the change was tested on.

## Before opening a pull request

```bash
bash -n scripts/*.sh
./scripts/sync-source.sh --check
python3 scripts/check-links.py
./scripts/build.sh --dry-run
```

If you changed the build wrapper, also do a real local build following
[`docs/BUILDING.md`](docs/BUILDING.md) and include the toolchain versions in the PR description.

### Testing checklist for kernel changes

- [ ] Boots on at least one `miatoll` device (state the codename and ROM).
- [ ] Wi-Fi, Bluetooth, camera, fingerprint, audio, charging and deep sleep verified.
- [ ] `dmesg` free of new warnings; no regressed `pstore`/`ramoops` dumps.
- [ ] Stock `boot`/`dtbo` backup available for recovery.
- [ ] `CONFIG_LOCALVERSION` and the final `.config` recorded in the PR.

## Pull requests

- Target `main` from a topic branch; see [`docs/BRANCHING.md`](docs/BRANCHING.md) for how the
  `17` development line relates to `main`.
- Fill in the pull request template, including the provenance block (kernel release, defconfig,
  source commit, Clang/LLD versions).
- CI (`Validate`) must pass. It only checks this repository's docs and scripts — it does not build
  a kernel.

Issues: use the bug report template and always attach `dmesg`/`pstore` logs plus the exact device,
ROM and kernel version.
